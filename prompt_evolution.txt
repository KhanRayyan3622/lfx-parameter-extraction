- Parameter = Implementation-specific choice (different implementations choose different values)

1. name: Parameter name
2. long_name: Full description
3. description: What it controls
4. type: enum, mask.value_pair, or integer_range
5. legal_values: What values implementations can choose
6. spec_section: Where mentioned
7. confidence: HIGH/MEDIUM/LOW based on textual evidence

REALITY CHECK: For each candidate, ask:
- Is this explicitly labeled implementation-specific/implementation-defined?
- Would two different RISC-V cores choose DIFFERENT values for this?
- If implementation can't choose, it's NOT a parameter.

Example cache block size: Implementations choose 32, 64, 128, 256... → PARAMETER
Example CSR address format: All implementations use same 12-bit format → CONVENTION, NOT PARAMETER"
